# .harness/trust.txt — who may command the harness, and how much (B269/D60).
#
# Format: `<level> <handle>`, one per line, optionally followed by `vouch:<id>` (D68, below).
# '#' starts a comment. Case-insensitive.
# A handle with no level is read as level 1 and `harness doctor` names it — least privilege
# on ambiguity, loudly, because a typo here must never silently grant power.
#
#   3  operator    everything, including `reject`, the one verb that ends a work item
#   2  maintainer  create and steer: work, queue, audit, promote, go, revise, fix, rebase,
#                  split, stop
#   1  asker       `ask` only; changes no state
#   0  everyone else — the absence of a line. The comment is read, denied, and ignored.
#
# The level is only half the gate: GitHub must also report the commenter as OWNER, MEMBER or
# COLLABORATOR on the repository the comment is on (B131). Neither half suffices alone — unless
# the line vouches for one exact account, which takes the place of the association (D68).
#
# Changing this file requires a reviewed PR (see .github/CODEOWNERS).
3 jgoetzmann

# comment from the login BrightBoost-Tech whose `user.id` is 193453438 passes the association
# half of the gate on every repository, whatever GitHub reports about it. Without the vouch its

# its association is. The level still caps what it may do: level 2 does not get `halt`,
# `resume`, `reject` or `--force`.
#

# The vouch is instead of repository access, not as well as it: do not invite this account.

# TO ADD A MAINTAINER, TWO THINGS. Both, or their comments are read, denied and ignored:
#
#   1. add one line here: the digit 2, a space, then their GitHub handle; and
#   2. EITHER invite them to THIS repository, so GitHub reports them as a collaborator,
#      OR, if they must not have access here, end the line with `vouch:` and their numeric
#      account id — the `id` field of `GET https://api.github.com/users/<handle>`. A vouch
#      admits that one account on every repository and nobody else under that name (D68).
#
# The second is the half people forget, and it fails silently from their side -- a denied
# comment looks exactly like the harness being asleep. `harness doctor` names anyone listed
# here who has no access and no vouch, which is the only way to see it without asking them to
# test it. Nothing else is needed -- no restart, no secret. The next sweep reads the file fresh.
#
# A malformed vouch — `vouch:` with no id, anything but digits after it, or two of them —
# refuses the WHOLE line: it grants nothing, and `harness doctor` names it. It is never read as
# "no vouch", which would grant something else.
#
# Every line naming a vouched handle must carry the same vouch. Two different ids, or a vouched
# line beside a bare one for the same handle, refuse EVERY line naming it: `3 x` beside
# `2 x vouch:1` would otherwise give account 1 level 3 with no association, which neither line
# grants alone. To change a vouched handle's level, change its one line.
#
# Do not park a fill-me-in name here first. `Identity.trust_file_ready()` refuses the WHOLE
# file when a placeholder token survives anywhere in it, comments included, so a half-filled
# line does not sit harmlessly: it fails the tier check in `harness doctor` and takes the two
# real handles down with it. Add the line when you have the handle.
