# .harness/trust.txt — who may command the harness, and how much (B269/D60, D69).
#
# TO ADD SOMEBODY, ONE LINE. It works on every repository, needs no invitation, and gives
# nobody any access to anything:
#
#     2 their-github-login vouch:their-numeric-account-id
#
# `harness trust line <login> --level 2` prints that line for you, account id and all. Paste it
# below and open a pull request — this file is CODEOWNERS-protected, and the harness cannot
# write it (B143), so a reviewed PR is the only way in and is the whole security boundary. The
# next sweep reads the file fresh: no restart, no secret, nothing to redeploy.
#
# The id is the `id` field of `GET https://api.github.com/users/<login>`. It pins the line to
# ONE account: that account is heard wherever it comments, whatever GitHub reports about it,
# and any OTHER account holding the same login is refused (D68). It must be a PERSON: an
# organisation has an account id too and never authors a comment, so vouching for one admits
# nobody at all. `harness trust line` refuses to print such a line and `harness doctor` names
# one already here.
#
# Format: `<level> <handle>`, optionally followed by `vouch:<id>`. One per line. '#' starts a
# comment. Case-insensitive.
#
# What each level may give. This table is checked against `keywords.VERB_LEVEL` by
# `tests/test_docs_drift.py`, so it cannot drift from what the gate enforces:
#
#   3  operator    halt, resume, reject — and everything below
#   2  maintainer  audit, go, promote, rebase, revise, split, stop, work
#   1  asker       ask, status
#   0  everyone else — the absence of a line. The comment is read, denied, and ignored.
#
# Level 1 is not "free": `ask` reads the product repository and spends a model call (bounded by
# ASK_CAP_USD); `status` costs nothing. Level 2 is not merely "can't halt": in the four stages
# with nowhere to park an item, its `stop` ends that item for good. docs/COMMANDS.md has both.
#
# WITHOUT a vouch, a line still needs GitHub to report the commenter as OWNER, MEMBER or
# COLLABORATOR on the repository the comment is on (B131) — in practice, an invitation. That
# route still works and needs no id, so use it for somebody who is already a collaborator. It
# is per-repository and invisible from the commenter's side, which is why the vouched form
# above is the one to reach for.
#
# A line that would grant nothing is never quietly read as something smaller. The WHOLE line is
# refused, and `harness doctor` names it, when:
#   - the level is not 1, 2 or 3;
#   - the handle is not a GitHub login — letters, digits and hyphens only, so no email
#     addresses, no trailing commas, no two-word names;
#   - anything follows the handle except one well-formed `vouch:<id>`. In particular a bare
#     account id with the keyword left off looks right, reads as a plain line, and vouches for
#     nobody;
#   - two lines naming one handle disagree about which account it is (D68).
#
# `harness trust show` prints this file exactly as the gate reads it, including every entry
# that is being refused and every handle that still depends on the association half.
#
# Do not park a fill-me-in name here. ANY `<...>` placeholder is skipped (doctor names it), and
# `Identity.trust_file_ready()` fails the WHOLE file while one is present, taking the real
# handles down with it — it reads the same parser this gate does, so the two agree about what
# an unfinished line is. Add the line when you have the handle.
